## 4. A3 输出头 2×2（train 内部 80/20，变体 `struct_no_history`）

| 头型 | 参数量 | code bits ↓ | vs tied | vs source(9073.71) | best step |
|---|---:|---:|---:|---:|---:|
| tied（现状） | 7,997,088 | 9207.46 | — | −133.74 | 19000 |
| untied | 12,191,392 | 9549.15 | **−341.70** | −475.44 | 20000 |
| **tied + copy gate** | **8,015,520** | **8772.70** | **+434.76** | **+301.02** | 19000 |
| untied + copy gate | 12,209,824 | 8818.27 | +389.19 | +255.45 | 19000 |

```
copy gate 效应 (tied)   : +434.76      解绑效应 (无门) : −341.70  ← 有害
copy gate 效应 (untied) : +730.88      解绑效应 (有门) :  −45.57
交互                    : −296.13
copy gate 仅多 18,432 个参数（+0.23%）
```

**结论修正**：此前基于「学到的 tied 基（+2.00）远差于最优自由 rank-8 基（+0.02）」推断
「瓶颈是 tied，应先解绑」是**错的**。解绑多花 419 万参数反而倒退 341.70 bit。正确解读：
tied 基之所以差，是因为它被要求编码 persistence（`Δ·I₂₅₆`，rank 256），那是结构上做不到的；
给自由度只会在 31,555 条转移上过拟合。修法是把负担**移走**（copy gate 显式注入单位阵）。
交互项 −296.13 印证：有门之后解绑的害处从 −341.70 收敛到 −45.57。

## 5. 其他只读 pilot 结论

- 缺口 100% 在 code 通道：code +68.96，mask **−1.51**（模型在 mask 上赢 source）。
- 温度校准基本无效：τ\*≈1.05，增益 ≈0.7 bit；ECE=0.021 但**非单调**（低分段欠自信、
  高分段过自信），单个 τ 结构上修不了。
- rank-8 KL 投影惩罚 ~0.42 bit/code（×2048 ≈ 850 bit）；r=64→0.10，r=128→0.01。
- source 的 `source_n` 仅 10–18 → **copy 先验承载 85–92% 的质量**。要打败的主体是
  persistence 模型，不是复杂 256×256 转移表。
- step 曲线（step0 +374 → step6 −737）被两件事混淆：任务组成，以及 **episode 存活选择**
  （step6 的观测只可能来自活到 step6 的 episode，episode 固定效应**消不掉**这一条，
  需 balanced survivor cohort：只取 length≥7 的 episode 内部比较）。
- task×step cell 表：8/10 任务构成完整 7 步面板，4 个空 cell 全在 `enter-text`/`scroll-text-2`
  的 step 5–6；14 个 cell n<30。

## 8. 已知的正式流程约束

- `rate_scope` **对任何模型参数都不计费** —— 神经权重与 baseline 的计数表同样不计。
  所以 source-prior 模型与 source 基线口径完全一致。指标是 held-out 预测码长，非两部分 MDL。
- `statistics.py` 要求 5 个 VARIANTS × seeds{0,1,2} = 15 个 run，
  `{resolved_core, parameter_count, parameter_shapes}` 逐字节一致 →
  新头参数必须在 `initialize_params` 里**无条件**创建，新超参必须进 `ModelConfig`。
- `freeze.py` 的 16 文件硬编码列表里没有 `source_kernel.py`，且 kernel 从不落盘。
- `rollout.py` 的 jit `step(params,batch)` 无 prior 通道，`_device_batch` 只留
  `MODEL_BATCH_KEYS`；但 `_replace_prefix` 已把预测码字写进 `history_codes[:,-1]`。
  **不能用闭包捕获**（6.4GB 表会烘进 jit 图）。
- `ALPHA=0.5`/`SOURCE_PRIOR_CONCENTRATION=128` 硬编码，被 `source_kernel.py` import，
  改动会同时改变 baseline 并使冻结 npz 失效。
- 测试当前 27/28：`test_fp64_evaluation_is_batch_partition_invariant` 在 jax 0.10.2 下失败
  （eval batch 切分不同 → XLA 选不同 kernel → per-transition fp32 差 ~1e-7；且
  `mask_accuracy`/`code_accuracy` 本就是 fp32 batch 均值加权累加）。阈值 1e-12 过严，
  折算到 9055 bit 量级约 1e-4 bit。
