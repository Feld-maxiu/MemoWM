# AMA-WEB QA 实验记录（2026-09-01）

## 1. 实验结论

本次使用冻结的 SyQA QFormer、冻结的 `512→5120` Bridge 和冻结的 Qwen3-32B Reader，在 AMA-Bench 的 WEB 开放式 QA 子集上完成正式评测。

- 有效 trajectory：30 个
- 有效 QA：360 条
- 跳过：episode 184（整条 trajectory，共 12 个 QA，不进入生成和评分）
- AMA 官方 LLM-as-Judge 正确数：87/360
- 最终准确率：**24.17%**

该结果仅代表本次 `matched memory + top_k=1` 配置。当前没有在相同数据和 Judge 配置下运行 question-only、shuffled-memory 或无 latent-memory 基线，因此不能仅凭本次结果归因 QFormer/Bridge 的净增益。

## 2. 模型链路

```text
AMA-WEB trajectory
        │
        ▼
冻结 Qwen3.5-9B trunk
        │  trajectory states
        ▼
冻结 SyQA QFormer + retrieval head
        │  xbar / 512 维 latent memory
        ▼
冻结 512→5120 Bridge（RMS 对齐 Qwen3-32B input embedding）
        │  5120 维 memory embeddings
        ▼
冻结 Qwen3-32B Reader
        │
        ▼
QA predicted answers
        │
        ▼
Qwen3-32B AMA LLM-as-Judge
```

本次评测没有更新 QFormer、Bridge、trunk 或 Reader 参数。

## 9. 本次运行中的关键修复

1. Batch=4 generation 修复：不再向 Hugging Face `generate()` 显式传入固定 `position_ids`，让生成过程自行推进 position，避免批量生成异常。修复后保留 batch=4。
2. Episode 184：从 cache、answer generation 和 Judge 输入中整条排除。
3. 执行顺序：取消流式 Judge，改为等待 `ANSWERS_COMPLETE` 后统一评分。
4. vLLM 启动：关闭 FlashInfer sampler，并使用 `--enforce-eager`，避免本机 CUDA JIT/额外编译进程导致启动失败或 OOM。
5. Judge 客户端：为旧版 OpenAI SDK 显式提供 `httpx.Client`，兼容 `openai 1.29.0 + httpx 0.28.1`。
6. Tokenizer 初始化：增加线程锁，避免 3 个评分 worker 首次并发导入/初始化 tokenizer 时发生竞态。
7. Judge 加速：最终采用 GPU3、GPU4、GPU5 三个数据并行模型副本，不采用 3 路 tensor parallel。

前面的失败启动没有写入最终 `evaluation.json`，最终结果来自修复后的完整 360 条统一重跑。

## 11. 建议的后续对照实验

为了判断 24.17% 的来源，后续应保持同一批 360 个 QA、同一 Reader、同一 Judge，并至少补充：

1. `question-only` / 无 trajectory memory；
2. shuffled trajectory memory；
3. matched memory（本次结果）；
4. 如 Bridge 支持，再比较不同 `top_k`。

只有这些对照使用完全一致的生成与 Judge 设置时，才能量化 QFormer/Bridge latent memory 的实际贡献。
